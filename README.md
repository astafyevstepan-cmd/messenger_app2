# 💬 Messenger — простой веб-мессенджер с аккаунтами

Полноценный мессенджер, доступный с любого устройства через браузер.
Каждый пользователь регистрируется под своим логином и паролем, сообщения
хранятся на сервере (SQLite), а обмен происходит в реальном времени через
Socket.IO — как в Telegram/WhatsApp Web.

## Возможности

- 🔐 Регистрация и вход по логину/паролю (пароли хэшируются bcrypt, сессия — JWT)
- 🌍 Доступ с любого устройства — телефон, планшет, другой компьютер (просто открой ссылку и залогинься)
- 💬 Обмен сообщениями в реальном времени (Socket.IO)
- 🔍 Поиск пользователей по имени/логину, чтобы начать новый чат
- 🟢 Индикатор "онлайн/оффлайн" и статус "печатает..."
- 📜 История переписки хранится в базе данных на сервере (SQLite)
- 📱 Адаптивный интерфейс в тёмной теме (стиль Telegram)

## Быстрый старт (локально)

```bash
cd messenger-app
npm install
cp .env.example .env      # при желании поменяй JWT_SECRET
npm start
```

Сервер поднимется на `http://localhost:3000`. Открой этот адрес в браузере,
зарегистрируй пару аккаунтов (можно в двух разных окнах / инкогнито) и начни переписку.

## Как открыть с других устройств (в локальной сети / по Wi-Fi)

Это основной сценарий использования — один компьютер работает как сервер,
а все остальные (телефоны, ноутбуки, планшеты) в **той же Wi-Fi сети**
заходят на сайт через браузер. Интернет для этого не нужен.

1. Убедись, что компьютер-сервер и все устройства подключены к **одному
   Wi-Fi роутеру** (одна и та же сеть).
2. Запусти сервер:
   ```bash
   npm start
   ```
3. При запуске сервер сам покажет нужный адрес, например:
   ```
   ========================================
     Мессенджер запущен!
   ========================================
     На этом компьютере:  http://localhost:3000
     С других устройств в этой Wi-Fi сети:
       → http://192.168.1.25:3000
   ========================================
   ```
   Просто скопируй адрес из строки "С других устройств..." — ничего вручную искать не нужно.
   (Если появилось несколько адресов — обычно нужен тот, что начинается с `192.168.` или `10.`)
4. На телефоне/планшете/другом ноутбуке открой браузер и вбей этот адрес,
   например `http://192.168.1.25:3000`.
5. На каждом устройстве зарегистрируй свой аккаунт (или войди в уже
   созданный) — и можно переписываться в реальном времени.

### Возможные проблемы

- **Не открывается с телефона** — почти всегда виноват файрвол на
  компьютере-сервере. На Windows при первом запуске `npm start` система
  спросит "Разрешить доступ в общедоступных и частных сетях?" — обязательно
  разреши (для приватной сети точно, для публичной — если сеть у тебя дома
  считается общедоступной). Можно вручную открыть порт 3000:
  - Windows: Панель управления → Брандмауэр Windows → Разрешить приложение → добавить node.exe (или создать правило на входящие TCP 3000)
  - macOS: Системные настройки → Сеть → Брандмауэр → разрешить входящие для Node
- **Не работает через мобильный интернет (LTE/4G) на телефоне** — это
  ожидаемо: телефон должен быть подключён к тому же Wi-Fi, а не к своим
  мобильным данным. Отключи мобильный интернет и подключись к Wi-Fi.
- **Гостевая Wi-Fi сеть роутера** — многие роутеры изолируют устройства в
  гостевой сети друг от друга ("Client Isolation"). Если не получается
  достучаться — попробуй основную сеть Wi-Fi, а не гостевую.
- **IP-адрес может поменяться** после перезагрузки роутера или сервера —
  тогда просто ещё раз запусти `npm start` и посмотри свежий адрес в
  консоли. Чтобы IP не менялся, можно закрепить его за компьютером в
  настройках роутера (DHCP reservation / статический IP).
- Сервер должен быть **постоянно запущен** (окно терминала открыто), пока
  им пользуются остальные — если закрыть терминал или выключить компьютер,
  сайт станет недоступен для всех.

## Как выложить в интернет (чтобы работало из любой точки мира)

Самый простой вариант — бесплатный/недорогой хостинг Node.js-приложений:

### Вариант 1: Render.com (проще всего, есть бесплатный план)
1. Залей проект на GitHub.
2. На render.com → New → Web Service → подключи репозиторий.
3. Build Command: `npm install`
4. Start Command: `npm start`
5. В Environment добавь переменную `JWT_SECRET` со своим случайным значением.
6. Render выдаст публичный URL вида `https://your-app.onrender.com` — открывай его с любого устройства.

### Вариант 2: Railway.app
Аналогично: подключаешь GitHub-репозиторий, Railway сам определяет Node.js
проект, нужно только выставить переменную окружения `JWT_SECRET`.

### Вариант 3: свой VPS (DigitalOcean, Timeweb и т.п.)
```bash
git clone <твой репозиторий>
cd messenger-app
npm install
npm install -g pm2
pm2 start server.js --name messenger
pm2 save
```
Дальше настрой Nginx как reverse-proxy на порт 3000 и подключи бесплатный
SSL-сертификат через Let's Encrypt (certbot) — тогда сайт будет доступен
по `https://твой-домен.ру`.

> ⚠️ Важно: база данных — это файл `messenger.db` рядом с сервером.
> На бесплатных тарифах некоторых хостингов (Render free) файловая система
> может очищаться при пересборке — для продакшена лучше подключить
> постоянный диск (Render Disk) или перейти на облачную БД (Postgres).

## Структура проекта

```
messenger-app/
├── server.js        # Express + Socket.IO сервер, вся бизнес-логика и API
├── db.js             # Инициализация SQLite базы данных (таблицы users, messages)
├── package.json
├── .env.example       # Пример переменных окружения
└── public/
    ├── index.html     # Разметка: экран логина/регистрации + сам мессенджер
    ├── style.css       # Стили (тёмная тема)
    └── app.js          # Клиентская логика: авторизация, чаты, Socket.IO
```

## Технологии

- **Backend:** Node.js, Express 5, Socket.IO, better-sqlite3, bcryptjs, jsonwebtoken
- **Frontend:** чистые HTML/CSS/JavaScript (без фреймворков)
- **База данных:** SQLite (файл `messenger.db`, создаётся автоматически при первом запуске)

## Безопасность

- Пароли хранятся только в виде bcrypt-хэшей — никогда в открытом виде
- Авторизация через JWT-токен (хранится в httpOnly cookie + дублируется в localStorage для Socket.IO)
- Перед продакшен-деплоем обязательно смени `JWT_SECRET` в `.env` на длинную случайную строку
